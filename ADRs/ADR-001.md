## Decisão

/Explique claramente qual decisão foi tomada./ 

Ao iniciar o projeto será utilizado somente o prisma sem a utilização do drizzle, pois a adição de complexidade para esse momento não é necessária.

Também foi escolhido o fastify por ser mais performatico nesse primeiro momento já que será um MVP com pouca complexidade. 

Também será utilizado a arquitetura de eventos tendo em vista que podém acontecer vários eventos após uma determinada ação acontecer. 
EX: completar a quest, dispara o evento de auterar pontuação e verificação de update de level. 

Também foi escolhido o React + Expo router + tamagui para começar de forma rapida e com pouca complexidade o que o expo + react native traria. 

posivelmente com a decisão de utilizar somente o react o sistema de notificações terá que ser externo como SMS e/ou whatsapp 

Monolito modular ja que é a fase inicial do projeto.

# ADR-001 — Modular Monolith Architecture

## Status

- Accepted

---

## Date

2026-07-08

---

## Context

Which architecture should be used for the frontend, backend, and database?

Which ORM should be adopted?

What are the current limitations?

Which requirements influence this decision?

---

## Decision

At the beginning of the project, only Prisma will be used. Drizzle ORM will not be adopted at this stage, as the additional complexity does not provide enough value for the initial MVP.

Fastify was selected as the backend framework because it offers better performance and lower overhead, which is appropriate for an MVP with relatively low complexity.

The application will also adopt an event-driven architecture, since a single action may trigger multiple business events.
Example: Completing a quest triggers like Score update, Level-up eligibility verification.

For the frontend, the chosen stack is React + Expo Router + Tamagui. This combination enables rapid development while taking advantage of the React ecosystem and reducing the complexity typically associated with a full React Native setup.

One consequence of prioritizing React is that native push notifications may not be available initially. Therefore, notifications will likely rely on external channels such as SMS and/or WhatsApp.

The system will be implemented as a modular monolith, since this is the initial phase of the project. This architecture provides clear domain boundaries while avoiding the operational complexity of microservices.

## Alternatives Considered

### Alternative 1

Description

Frontend using React + Expo Router + Tamagui

Pros

- Faster MVP development
- Easier testing across multiple devices
- Shared React ecosystem
- Lower architectural complexity

Cons

- Notifications will likely rely on external services such as SMS or WhatsApp
- Initial project setup requires more configuration

---

### Alternative 2

Description

Frontend using React Native + Expo + NativeWind

Pros

- Native mobile application experience
- Full access to native platform capabilities
- Better support for native notifications and device integrations

Cons

- Higher development complexity
- Testing is more dependent on physical devices or emulators

---

## Consequences

### Positive

- Faster development
- Lower coupling between modules
- Better application performance
- Easier maintenance during the MVP phase

### Negative

- Longer initial project setup
- Notification capabilities will be limited in the first version and may require external providers
