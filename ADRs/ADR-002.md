## Decisão

/Explique claramente qual decisão foi tomada./ 

Ao iniciar o projeto a ideia seria utilizar o react + expo router. mas com o decorrer descobrimos que o expo router utiliza o react native como referencia, e seria a melhor opçao já que estamos visando mobile-first e somente o react não seria possível, 
porem todo esse primeiro desenvolvimento será feito em cima do react native web o que permite que o desenvolvimento seja mais assistido.

# ADR-001 — Adoption of React Query and React Native

## Status

* Accepted

---

## Date

2026-07-22

---

## Context

Which frontend architecture should be used?

### Existing Limitations

* Future scalability concerns when using only React.
* Uncertainty about whether React Query would introduce unnecessary complexity at the beginning of the project.

### Influencing Requirements

* Most of the application's data interactions will come from server requests rather than local application state management.

---

## Decision

Initially, the plan was to use **React + Expo Router**. However, during the architecture evaluation, it became clear that **Expo Router is built around React Native** and that React Native is the better choice for a **mobile-first strategy**.

Because of this, the project will adopt **React Native + Expo Router** as the frontend foundation.

To improve the development experience, the initial implementation will be developed primarily using **React Native Web**, allowing faster feedback loops, easier debugging, and a more assisted development workflow while maintaining compatibility with native mobile platforms.

---

## Alternatives Considered

### Alternative 1

**Description**

Frontend using **React + React Router + Tamagui**

### Pros

- Faster MVP development
- Easier testing across different devices
- Simpler local development workflow
- Pure React requires less initial configuration

### Cons

- Native notifications would not be available by default
- Notifications would likely require external services such as SMS or WhatsApp

---

### Alternative 2

**Description**

Frontend using **React Native + Expo Router + NativeWind**

**Pros**

- Native mobile application experience
- Full access to standard mobile app capabilities
- Better long-term scalability
- React Native Web enables real-time testing and a more efficient development workflow
- Native notification support is available

**Cons**

- Slightly higher development complexity
- Testing may become more dependent on physical devices or emulators when React Native Web is not used
- Initial setup is more time-consuming and requires the appropriate SDK installation

**Neutral**

- Clear separation and organization of components

---

## Consequences

### Positive

- Better alignment between technology choices and product requirements
- More suitable architecture for the business domain
- Native notification capabilities become available again
- Stronger foundation for future mobile expansion

### Negative

- Longer initial setup and configuration process
